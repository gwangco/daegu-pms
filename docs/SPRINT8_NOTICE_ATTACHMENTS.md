# 8차 스프린트 — 공지사항 첨부파일

작업일: 2026-10-23 · 브랜치: `feature/sprint8-notice-attachments` · 이전 문서: [7차 스프린트](SPRINT7_DESIGN_RENEWAL.md)

## 한눈에 보기

- 공지사항에 파일을 붙일 수 있다. 공지 하나에 3개, 파일당 10MB.
- 이 규칙은 코드가 아니라 **게시판 속성**(공통컴포넌트 `COMTNBBSMASTER`)에 있다. 값을 바꾸면 규칙이 바뀐다.
- 공지 첨부는 비로그인도 내려받는다. 삭제된 공지의 파일은 받을 수 없다.

## 1. 범위

6차에 공지사항을 전자정부 공통컴포넌트 게시판으로 옮길 때 첨부파일은 미뤄 두었다(게시판 속성 "첨부 불가"). 이번에 게시판과 첨부파일 공통컴포넌트를 연결했다.

함께 고친 것: 공통컴포넌트 첨부파일 삭제가 DB 롤백과 어긋날 수 있던 문제 (5절).

## 4. 정한 것 다섯 가지

**① 규칙은 게시판 속성에 둔다.** 공통컴포넌트 게시판은 게시판마다 첨부 가능 여부(`FILE_ATCH_POSBL_AT`), 개수(`ATCH_POSBL_FILE_NUMBER`), 크기(`ATCH_POSBL_FILE_SIZE`, 바이트)를 둔다. 서비스가 이 값으로 검사하므로, 운영 중에 "첨부 금지"로 바꾸려면 값만 `N` 으로 고치면 된다. 테스트가 실제로 값을 `N` 으로 바꿔 업로드가 거부되는지 확인한다.

**② 첨부 ID 는 화면에서 받지 않는다.** 첨부파일 ID 는 `FILE_` + 순번이라 추측할 수 있다. 화면이 보낸 값을 믿으면 남의 첨부 묶음을 내 공지에 연결할 수 있다. 등록은 새로 만든 묶음, 수정은 잠근 게시물 행에서 읽은 묶음만 쓴다. 공통컴포넌트 원본(v5.0.7) 게시판 컨트롤러도 수정 때 같은 원칙(IDOR 조치)을 쓴다.

**③ 공개 범위는 "공개된 공지의 첨부"로 좁힌다.** 업무 첨부(사업계획서·정산 증빙) 주소 `/files/**` 는 그대로 로그인이 필요하다. 공지 첨부는 공지 번호 아래 주소로만 공개하고, 그 공지가 삭제되지 않았는지 매번 확인한다. 업무 첨부 주소로 공지 첨부를 요청하면 404 다.

**④ 순번은 행을 잠그고 매긴다.** 새 파일의 순번은 "지금 최대 순번 + 1"(`getMaxFileSN`)이다. 담당자 두 명이 같은 공지에 동시에 올리면 같은 순번을 받을 수 있어, 수정 전에 게시물 행을 `SELECT … FOR UPDATE` 로 잠근다. 또 새 파일을 **먼저 추가하고 나서** 지울 파일을 지운다. 반대로 하면 마지막 순번을 지웠을 때 새 파일이 같은 순번을 받아, 예전 다운로드 주소가 다른 파일을 가리킨다.

**⑤ 전부 검사한 뒤 저장한다.** 세 번째 파일이 형식 오류면 앞의 두 파일도 저장하지 않는다. 저장 중 오류가 나면 트랜잭션 롤백과 함께 디스크에 쓴 파일도 지운다. 오류가 나도 입력한 제목·내용은 화면에 그대로 남긴다(첨부파일은 브라우저 보안상 다시 선택해야 한다).

## 5. 공통컴포넌트에서 고친 것

| 파일 | 원본 | 바꾼 것 |
| :--- | :--- | :--- |
| `EgovFileMngServiceImpl.deleteFileInf` | DB 행을 지우기 **전에** 실제 파일 삭제 | DB 삭제 후 **커밋 뒤에** 실제 파일 삭제. 롤백되면 파일이 남는다 |
| `EgovArticle_SQL_mysql.xml` 등록 | (6차에 첨부 ID 를 비우도록 바꿔 둠) | 서버가 만든 첨부 ID 저장 |
| 〃 수정 | — | 첨부 ID 가 비어 있을 때만 연결 (`IFNULL`) |
| 〃 목록 | 첨부 ID 를 그대로 반환 | 파일이 남아 있을 때만 반환 (빈 묶음에 클립 표시 안 함) |

원본은 삭제 순서 때문에, 같은 요청에서 뒤에 오류가 나면 "DB 에는 있는데 파일은 없는" 상태가 된다. 이 경로를 처음 쓰는 기능이라 기능 커밋 전에 따로 고쳤다. 자세한 내역은 [COMMON_COMPONENTS.md](COMMON_COMPONENTS.md).

## 6. 검증

- `./mvnw clean verify` — 166건 성공. 공통컴포넌트 수정 커밋(156건)과 기능 커밋(166건) 각각 실행
- 실제 앱 (로컬 개발 DB) — 점검용 공지에 파일 2개 첨부, 비로그인으로 내려받아 원본과 바이트 비교 일치, 한글 파일 이름 `filename*=UTF-8''` 확인
- 헤드리스 Chrome — 수정 화면에서 기존 파일 2개 삭제 표시 + 새 파일 2개 선택 → 선택 안내에 파일 이름·크기와 남은 개수 표시, 제출 후 새 파일이 다음 순번(2, 3)으로 저장
- 화면 9건 — PC 1366px(메인·목록·상세·수정) 6건, 모바일 390px(목록·상세·수정) 3건. 가로 넘침·이름 없는 입력·콘솔 오류 모두 0
- Windows 의 curl 로 올리면 파일 이름이 깨진다(로컬 코드페이지로 보냄). 브라우저는 UTF-8 로 보내므로 정상 — 점검은 브라우저 경로로 했다
