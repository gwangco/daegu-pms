# 9차: 기업회원 가입

2026-10-23, 브랜치 `feature/sprint9-company-signup`

8차까지는 데모 계정으로만 들어갈 수 있었다. 이번에 기업이 직접 가입하고 관리자가 승인하는 흐름을 만들었다.

1. 약관과 개인정보 수집에 동의하고 계정, 기업, 담당자 정보를 입력한다
2. 가입은 승인 대기로 저장된다
3. 총괄관리자가 사용자 관리에서 승인하면 그때부터 로그인할 수 있다

![기업회원 가입 화면과 승인 대기 목록](images/company-signup.png)

## 왜 관리자 승인인가

본인인증이나 국세청 사업자 조회를 붙이지 않았으니 실제로 있는 기업인지는 사람이 확인해야 한다. 공통컴포넌트 원본도 기업회원 가입을 신청 상태로 저장하고 관리자가 승인한다. 승인 전에는 비밀번호가 맞아도 로그인되지 않고 "가입 승인을 기다리는 계정" 이라고 안내한다.

## 사업자등록번호 하나에 계정 하나

공고 중복 신청 검사가 계정 단위라서, 같은 기업이 계정을 둘 만들면 같은 공고에 두 번 신청할 수 있다. 그래서 기업회원끼리는 사업자등록번호가 겹치지 않게 했다.

담당자나 평가위원은 같은 기관이면 번호가 같을 수 있어서 컬럼 전체에 UNIQUE 를 걸 수는 없었다. MySQL 에는 조건부 인덱스가 없으니, 기업회원일 때만 값이 들어가는 생성 컬럼을 만들고 거기에 UNIQUE 를 걸었다. 서비스가 먼저 확인해서 안내하고, 동시에 들어온 가입은 DB 가 막는다.

## 입력 규칙은 서비스 한 곳에서

아이디, 비밀번호, 번호 규칙을 서비스에서 모두 확인하고 어긴 칸을 모아 한 번에 돌려준다. 사용자는 한 번에 다 고칠 수 있고, 화면을 거치지 않는 호출도 같은 규칙을 지난다. 권한과 승인 상태는 입력 VO 에 필드가 아예 없고 INSERT SQL 에 고정돼 있어서, 요청에 넣어도 바뀌지 않는다.

- 비밀번호: KISA 안내서 기준(3종류 조합이면 8자, 2종류면 10자 이상)에 아이디 포함, 같은 문자 3번 반복, 연속 문자 4자를 금지했다. BCrypt 는 앞 72바이트만 쓰기 때문에 최대 64자로 제한했다.
- 사업자등록번호: 하이픈이 있든 없든 `000-00-00000` 으로 맞춘 뒤 검증번호를 계산한다. 휴업이나 폐업 여부는 국세청 연계가 필요해서 승인할 때 사람이 확인한다.

## 공통컴포넌트와 다른 점

공통컴포넌트는 기업회원 전용 테이블을 따로 두고, 비밀번호를 아이디를 솔트로 한 SHA-256 으로 저장한다. 이 프로젝트는 사용자 테이블 하나를 권한으로 나누고 BCrypt 를 쓴다. 테이블은 가져오지 않고 승인 흐름만 원본과 맞췄다.
