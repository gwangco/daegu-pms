# 5차: 계정 보안, 개인정보, 화면 정리

2026-10-22, 브랜치 `feature/sprint5-account-privacy-ui`

4차에서 다음 할 일로 적어 둔 계정 잠금, 개인정보 암호화, 감사 컬럼, 공통 레이아웃을 만들었다. eGovFrame 도 5.0.2 에서 5.1.0 으로 올렸다.

## 바뀐 것

- 로그인 5회 연속 실패 시 30분 잠금, 접속 기록, 관리자 잠금 해제
- 연락처와 이메일을 eGov ARIA 암호화로 저장, 관리자 목록에는 가린 값만 표시
- 수정자와 수정일시를 MyBatis 인터셉터가 모든 SQL 에 자동으로 넣음
- 정산 반려 건을 보완해서 다시 요청, 처리 이력, 담당자 검수함
- 공통 레이아웃, WebJars, CSP, 접근성 기본 요소
- 메인 화면에 역할별 처리할 일
- 엑셀 다운로드를 SXSSF 스트리밍으로 변경
- FAQ 추가 (eGov 코드 생성기로 만든 뒤 보완)

## 로그인 실패 횟수도 동시에 들어오면 틀린다

틀린 비밀번호 요청 두 개가 동시에 실패 횟수 3을 읽고 각자 4로 저장하면, 두 번 틀렸는데 한 번만 센다. 이걸 반복하면 잠금을 늦출 수 있다. 사용자 행을 `FOR UPDATE` 로 잠근 뒤 횟수를 계산하게 해서 같은 계정의 실패는 차례로 처리되게 했다.

잠긴 계정은 비밀번호를 비교하기 전에 거부한다. 잠긴 동안에는 비밀번호가 맞았는지도 알려 주지 않는다.

## 개인정보 암호화

`EgovARIACryptoService` 로 연락처와 이메일을 `{ARIA}` + Base64 형태로 저장한다. 앞의 표식으로 평문과 구분되니 기존 데이터를 차례로 바꿀 수 있었다.

- 키는 저장소에 두지 않고 환경변수로 넣는다. 키 길이나 해시가 맞지 않으면 서버가 뜨지 않는다.
- 같은 평문은 항상 같은 암호문이 된다. 같은 값끼리 비교는 되지만, 어떤 값이 몇 번 나오는지는 드러난다.
- 암호화 라이브러리의 DEBUG 로그가 평문과 키를 출력해서 해당 로그는 INFO 로 고정했다.
- 가리는 작업은 서버에서 한다. 조회 결과를 그대로 고치면 MyBatis 1차 캐시 안의 객체가 바뀌어, 같은 트랜잭션의 다음 조회가 가린 값을 받는다. 그래서 복사본을 만들어 가린다.

## 감사 컬럼

인터셉터가 SQL 에 값을 바인딩하기 직전에 `audit`(로그인 사용자, 현재 시각)를 넣는다. 매퍼에서는 `#{audit.userId}`, `#{audit.now}` 로 쓴다. 값은 로그인 정보와 Clock 에서만 가져오므로 요청 값으로 바꿀 수 없다. 배치처럼 로그인 사용자가 없으면 `SYSTEM` 이 남는다.

## 정산 재요청과 1차 캐시

재요청은 과제 행을 잠그고, 정산 건을 다시 읽고, 금액과 잔액을 다시 검사한 뒤 저장한다. 그런데 잠그기 전에 읽은 결과가 MyBatis 1차 캐시에 남아 있으면, 잠근 뒤 다시 읽어도 캐시를 돌려줘서 재검사가 의미가 없었다. `localCacheScope` 를 `STATEMENT` 로 바꿨다.

## 화면

- 공통 레이아웃을 만들고 인라인 스크립트를 공통 스크립트로 옮겨 CSP(`script-src 'self'`)를 적용했다.
- 헤드리스 Chrome 으로 32개 화면을 1366px, 390px 폭에서 열어 CSP 위반, 콘솔 오류, 가로 넘침이 없는지 봤다.
- 목록 표마다 세로 스크롤바가 생겼다. 표 높이가 소수점이라 1px 넘친 것이 원인이었고 `overflow-y: hidden` 으로 고쳤다.

## 일부러 규칙을 깨 보기

| 해 본 것 | 결과 |
| :--- | :--- |
| `select*` 읽기 전용 규칙 삭제 | 트랜잭션 규칙 테스트 실패 |
| 잠금 SQL 에서 `FOR UPDATE` 삭제 | 동시성 테스트 4건 실패 |
| 메시지 키에 오타 | 처음에는 통과했다. 키를 변수로 넘겨서 검사가 찾지 못한 것이었다. 호출하는 곳에 키를 직접 적게 고친 뒤에는 실패한다 |

테스트가 통과해도 그 테스트가 정말 그 상황을 보고 있는지는 따로 확인해야 한다.
