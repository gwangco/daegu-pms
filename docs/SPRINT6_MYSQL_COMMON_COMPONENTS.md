# 6차: MySQL 전환과 공통컴포넌트 도입

2026-10-22, 브랜치 `feature/sprint6-common-components-mysql`

실무 eGov 프로젝트와 가장 다른 점 세 가지를 바꿨다.

1. 개발 도구를 VS Code 에서 Eclipse 로 ([설정 방법](ECLIPSE_SETUP.md))
2. DB 를 H2 인메모리에서 MySQL 8 로, 스키마는 Flyway 로 관리
3. 직접 만들었던 공통코드, 첨부파일, 공지, FAQ, 채번을 전자정부 공통컴포넌트 v5.0.7 로 ([사용 내역](COMMON_COMPONENTS.md))

## Flyway

스키마 변경을 파일로 남겨 두고, 서버가 뜰 때 아직 적용하지 않은 파일만 순서대로 실행한다.

- `V1`: 기존 테이블을 MySQL 문법으로
- `V1_1`: 데모 데이터 (local, test 프로필에서만)
- `V2`: 옛 테이블 데이터를 공통컴포넌트 테이블로 옮기고 옛 테이블 삭제

V1 과 V2 를 나눈 건 이미 데이터가 쌓인 DB 를 공통컴포넌트 구조로 바꾸는 상황을 그대로 해 보고 싶어서였다. 적용한 파일을 고치면 체크섬이 달라져 서버가 뜨지 않으므로, 바꿀 것이 생기면 새 버전 파일을 추가한다.

Spring Boot 가 정한 Flyway 11.7.2 는 MySQL 8.4 를 검증하지 않은 버전이라 CI 에서 경고가 나서 11.20.3 으로 올렸다.

## DB 계정 분리

- `dpms_owner`: 테이블을 만들고 바꾸는 계정. Flyway 만 쓴다.
- `dpms_app`: 서버가 쓰는 계정. 조회, 등록, 수정, 삭제만 할 수 있다.

비밀번호는 저장소에 두지 않는다. 로컬은 `scripts/setup-local-mysql.ps1` 이 무작위 비밀번호를 만들어 Git 에서 빠진 파일에 저장하고, CI 는 실행할 때마다 새로 만든다. `application.yml` 에 기본값을 두지 않아서 비밀번호가 없으면 서버가 뜨지 않는다. 엉뚱한 계정으로 조용히 뜨는 것보다 낫다.

## H2 에서는 안 보이던 문제

- MySQL 드라이버는 DATETIME 을 `Timestamp` 가 아니라 `LocalDateTime` 으로 줘서 테스트 3건이 형변환에서 실패했다.
- 공통컴포넌트 게시판의 상세 조회는 조회수 UPDATE 를 같이 한다. 이 프로젝트는 `select*` 메서드를 읽기 전용 트랜잭션으로 두기 때문에 MySQL 이 `Connection is read-only` 로 거부했다. 조회와 조회수 증가를 나눠서 부르게 했다.
- 동시성 테스트의 잠금 대기 확인이 H2 전용 쿼리였다. `performance_schema.data_lock_waits` 로 바꿨다.
- MyBatis 별칭은 대소문자를 구분하지 않아서 공통컴포넌트의 `FileVO` 와 업무 쪽 `fileVO` 가 충돌했다. 업무 쪽을 지우고 공통컴포넌트 것을 쓴다.
- 로컬에서는 통과하는데 CI 에서만 계정 잠금 테스트가 실패했다. CI 시간대가 UTC 라서 `Timestamp` 로 넣은 시각이 9시간 밀려 저장된 것이었다. `LocalDateTime` 으로 바인딩하게 고치고, 같은 이유로 앱 시계와 마감 배치도 `Asia/Seoul` 로 고정했다.

## 공통컴포넌트

공통컴포넌트는 `egovframework.com` 패키지 그대로 두고 업무 서비스가 호출한다. 화면(JSP)과 컨트롤러는 가져오지 않았다.

그대로 쓸 수 없는 부분이 있었다.

- 원본은 모든 메서드를 쓰기 트랜잭션으로 둔다. 이 프로젝트 규칙(`select*` 는 읽기 전용)과 같이 쓰면 "조회하면서 조회수를 올리는" 메서드가 실패한다.
- 게시판과 FAQ 검색 SQL 이 `searchCnd == 0` 처럼 숫자로 비교해서, 문자 값이 들어오면 500 오류가 난다.
- 작성자 ID 와 첨부파일 ID 를 화면에서 온 값 그대로 저장한다. 서버 값으로 채우고 바인딩을 막았다.

고친 파일에는 머리말 개정이력을 남겼다. 나중에 원본을 업데이트할 때 무엇을 바꿨는지 바로 찾을 수 있다.
