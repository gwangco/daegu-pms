# 11차: 개인정보 처리 기록

2026-10-23, 브랜치 `feature/sprint11-privacy-access-log`

로그인과 로그아웃은 5차부터 남기고 있었다. 이번에는 로그인한 뒤 "누가 누구의 정보를 봤는지"를 남긴다. 담당자, 평가위원, 관리자가 남의 개인정보가 담긴 화면이나 파일을 보면 기록되고, 본인 정보를 본 것은 남기지 않는다.

기록 항목은 처리자, 일시, 접속 IP, 업무(조회, 다운로드), 대상, 정보주체, 건수다. 「개인정보의 안전성 확보조치 기준」의 접속기록 항목에 맞췄다. 총괄관리자는 시스템 관리 > 개인정보 처리 기록에서 처리자, 업무, 기간으로 찾아볼 수 있다.

![개인정보 처리 기록 화면](images/privacy-access-log.png)

## 기록하는 경우

- 담당자나 평가위원이 기업 신청서 상세를 열 때
- 사업계획서나 정산 증빙을 내려받을 때
- 신청 현황 엑셀을 내려받을 때 (건수는 엑셀 행 수)
- 총괄관리자가 사용자 목록을 열 때

## 기록은 컨트롤러에서 따로 쓴다

신청서 조회 서비스는 이름이 `select*` 라서 읽기 전용 트랜잭션으로 돈다. 그 안에서 INSERT 하면 MySQL 이 거부한다. 6차에 조회수 때문에 겪은 것과 같은 규칙이다. 그래서 조회가 끝난 뒤 컨트롤러가 기록 메서드(`insertPrivacyAccess`)를 따로 부른다. 이 메서드는 이름이 `insert*` 라 쓰기 트랜잭션이다.

처리자는 로그인 정보, 일시는 서버 시계, 접속지는 요청 IP 에서 가져온다. 화면에서 받는 값은 없다.

## 확인

- 테스트 238건 통과 (5건 추가)
- 담당자로 신청서를 열고 관리자로 사용자 목록을 연 뒤, 기록 화면에 처리자와 대상, IP 가 나오는지 확인

## 남은 것

- 보관 기간이 지난 기록 정리, 월간 점검 결과 남기기
- 기록 자체의 위·변조 방지 (다른 저장소로 보내기, 삭제 권한 분리)
