# 7차: 화면 개편 (KRDS 기준)

2026-10-23, 브랜치 `feature/sprint7-design-renewal`

6차까지는 기능에 집중해서 화면은 Bootstrap 기본 모양에 가까웠다. 실제로 띄워 보니 문제가 세 가지 있었다.

1. 공공 서비스처럼 보이지 않았다. 모든 영역이 같은 흰 카드라 어디를 먼저 봐야 할지 알기 어려웠다.
2. CSS 에 `Pretendard GOV` 를 적어 놓고 글꼴 파일이 없어서 실제로는 맑은 고딕으로 보였다.
3. 모바일에서 목록 표가 화면 폭의 두 배라 상태와 버튼이 화면 밖에 있었다.

KRDS(대한민국 정부 디자인 시스템) 기준으로 색, 글자, 버튼 크기를 바꾸고 메인, 목록, 상세, 입력 화면을 다시 배치했다. 업무 로직과 URL, DB 는 그대로다.

## KRDS 적용 방식

Bootstrap 은 그대로 두고 색, 글자 크기, 버튼 높이 같은 값(디자인 토큰)만 KRDS 값으로 바꿨다. CSS 변수는 세 단계로 나눴다.

- `--krds-*`: KRDS 원본 값
- `--dp-*`: 용도별 이름 (`--dp-primary`, `--dp-text` 등). 화면 CSS 는 이것만 쓴다
- `--bs-*`: Bootstrap 변수

색을 바꾸고 싶으면 한 곳만 고치면 된다.

KRDS 의 HTML 컴포넌트를 통째로 쓰지 않은 건 Bootstrap 과 클래스가 겹치고 템플릿 26개를 전부 다시 짜야 했기 때문이다. KRDS 의 공식 누리집 배너와 정부 상징도 쓰지 않았다. 이 시스템은 공식 누리집이 아니어서 데모 안내 띠를 그대로 둔다.

## 글꼴

KRDS 배포본에 있는 Pretendard GOV 서브셋(보통, 중간, 굵게)을 서버에 넣었다. CDN 을 쓰지 않은 건 인터넷이 막힌 망에서도 깨지지 않고, CSP 를 `font-src 'self'` 로 둘 수 있어서다. 라이선스는 SIL OFL 1.1 이고 `licenses/` 에 있다.

## 화면별로 바꾼 것

- 메인: 공고 검색창, 역할별 처리할 일, 진행 절차 4단계. 분야별 예산은 도넛 차트를 막대로 바꿨다. 다섯 항목의 크기를 비교할 때는 각도보다 길이가 읽기 쉽다. 차트가 없어져서 Chart.js 도 뺐다.
- 목록: 768px 미만에서는 표를 카드처럼 보여 준다. HTML 은 표 하나 그대로 두고 CSS 만 바꾼다. PC 용과 모바일용 화면을 따로 만들지 않으니 권한이나 상태 조건이 한 곳에만 있다.
- 상세: 본문 옆에 요약 카드를 두고, 신청 과제에는 진행 단계를 표시했다.
- 입력: 금액을 `1억 5,000만원` 처럼 한글 단위로 같이 보여 주고, 최대 지원금 초과나 잔액 초과는 미리 경고한다. 서버 검증은 그대로다.
- e-정산: 집행률 막대를 넣고, 모바일에서 안 보이던 반려 사유를 보이는 칸으로 옮겼다. 승인은 되돌릴 수 없어서 확인 창을 거친다.

모바일 카드는 칸마다 붙인 `data-label` 을 CSS 가 칸 앞에 붙여 주는 방식이다.

```html
<td data-label="신청 지원금" class="text-end">40,000,000원</td>
```

## 정적 리소스 캐시

전에는 CSS, JS, 글꼴을 화면을 옮길 때마다 새로 받았다(Spring Security 기본값 `no-store`). 이제 주소에 내용 해시를 붙이고 1년 동안 캐시한다. 파일이 바뀌면 해시도 바뀌니 새 주소로 다시 받는다. 화면(HTML)은 공용 PC 에 로그인 화면이 남지 않도록 계속 캐시하지 않는다.

## 명도 대비

| 대상 | 전 | 후 |
| :--- | :--- | :--- |
| 포커스 표시 | 1.7:1 | 6.8:1 |
| 입력칸 테두리 | 1.4:1 | 6.3:1 |
| 주 버튼 글자 | 없음 | 4.55:1 |

기준은 포커스와 테두리 3:1, 글자 4.5:1 이다.

## 확인

- 테스트 156건 통과
- 헤드리스 Chrome 으로 35개 화면을 1366px, 390px 에서 캡처해 콘솔 오류, CSP 위반, 가로 넘침이 없는지 확인
- 금액 안내, 정산 부가세와 잔액 초과, 집행률 막대는 직접 입력해 보고 확인
