# 7차 스프린트 — 화면 디자인 개편 (KRDS 기준)

작업일: 2026-10-23 · 브랜치: `feature/sprint7-design-renewal` · 이전 문서: [6차 스프린트](SPRINT6_MYSQL_COMMON_COMPONENTS.md)

## 1. 범위

6차까지는 기능과 실행환경을 다뤘고, 화면은 Bootstrap 기본 모양에 가까웠다. 실제 화면을 데스크톱·모바일로 띄워 보니 문제가 세 가지였다.

1. 공공 서비스처럼 보이지 않았다. 모든 영역이 같은 흰 카드라 어디를 먼저 봐야 할지 흐렸다.
2. CSS 에 `Pretendard GOV` 를 적어 두었지만 글꼴 파일이 없어 실제로는 맑은 고딕으로 보였다.
3. 모바일에서 목록 표가 화면 폭의 두 배였다(신청 목록 717px / 화면 350px). 상태와 버튼 칸이 화면 밖에 있었다.

이번에는 KRDS(대한민국 정부 디자인 시스템) 기준으로 색·글자·컴포넌트 크기를 바꾸고, 메인·목록·상세·입력 화면을 다시 배치했다. 업무 로직·URL·DB 는 바꾸지 않았다.

다크 모드·고대비 모드, 화면낭독기 실사용 점검은 이번 범위가 아니다.

## 3. KRDS 를 어떻게 적용했나

KRDS 는 공공 서비스용 "표준 자재 목록"에 가깝다. 이 프로젝트는 Bootstrap 이라는 골조는 그대로 두고, 색·글자 크기·버튼 높이 같은 규격만 KRDS 값으로 바꿨다.

```text
krds-uiux 1.1.0 (npm)                         dpms.css
--krds-color-light-primary-50  #256ef4   ─▶   --krds-primary-50 ─▶ --dp-primary    ─▶ .btn-primary
--krds-color-light-gray-60     #58616a   ─▶   --krds-gray-60    ─▶ --dp-line-input ─▶ .form-control 테두리
button size-height-6 (4rem = 40px)       ─▶   .btn { min-height: 2.5rem }
```

- 변수는 3단이다: KRDS 원본 값(`--krds-*`) → 용도 이름(`--dp-text`, `--dp-primary`) → Bootstrap 변수(`--bs-*`). 화면 CSS 는 용도 이름만 쓴다. 색을 바꿀 때 한 곳만 고친다.
- KRDS 는 html 글자 크기를 10px 로 두고 rem 을 쓴다(1.7rem = 17px). Bootstrap 은 16px 기준이라 px 로 환산해 옮겼다(17px = 1.0625rem).
- KRDS HTML 컴포넌트(CSS·JS)를 통째로 쓰지 않았다. Bootstrap 과 클래스·초기화 규칙이 겹치고, 화면 템플릿 26개를 모두 다시 짜야 한다. 값(토큰)만 가져오면 기존 마크업과 테스트를 유지하면서 모양을 맞출 수 있다.
- KRDS 의 "공식 누리집 배너"와 정부 상징은 쓰지 않았다. 이 시스템은 공식 누리집이 아니므로 데모 안내 띠를 그대로 둔다.
- 배포본은 npm 레지스트리의 SHA-512 무결성 값과 대조한 뒤 썼다. KRDS 자료는 저작권법 제24조의2(공공저작물 자유이용)에 따라 출처를 밝히고 쓴다 → [`licenses/krds-NOTICE.txt`](../licenses/krds-NOTICE.txt), 화면 푸터, README.

## 4. 글꼴

| 항목 | 내용 |
| :--- | :--- |
| 파일 | `static/fonts/pretendard-gov/PretendardGOV-{Regular,Medium,Bold}.subset.woff2` (각 약 260KB) |
| 출처 | KRDS 배포본의 서브셋을 고치지 않고 사용. 한글 2,780자 (완성형 2,350자 전부 포함, 프로젝트 소스에 쓰인 한글 540자 모두 있음) |
| 라이선스 | SIL OFL 1.1 ([`licenses/pretendard-gov-OFL-1.1.txt`](../licenses/pretendard-gov-OFL-1.1.txt), 글꼴 파일 안에도 같은 정보) |
| 불러오기 | `@font-face` + `font-display: swap`, 본문(Regular)은 `<link rel="preload">` 로 먼저 받음 |
| 없는 글자 | 서브셋에 없는 드문 한글은 시스템 글꼴로 보인다 |

CDN 을 쓰지 않은 이유는 Bootstrap 을 WebJar 로 넣은 이유와 같다. 인터넷이 막힌 망에서도 깨지지 않고, CSP `font-src 'self'` 를 그대로 둘 수 있다. 보안 설정의 비로그인 허용 경로에 `/fonts/**` 를 추가했다.

## 5. 화면별

### 메인

- 첫 화면은 검색창(사업공고 검색어로 이동)과 바로가기. 오른쪽 카드는 로그인하면 역할별 처리할 일, 로그인 전에는 전체 현황이다.
- 분야별 예산은 도넛 → 막대. 범주 5개의 크기 비교는 길이(막대)가 각도(도넛)보다 정확하다. 금액은 글자로 함께 쓰고 막대는 화면낭독기에서 숨긴다. 차트가 없어져 Chart.js 의존성을 뺐다.

### 목록 — 모바일 카드형

```html
<td data-label="신청 지원금" class="text-end">40,000,000원</td>
```

```css
@media (max-width: 767.98px) {
    .table-cards > tbody > tr > td[data-label]::before { content: attr(data-label); }   /* 항목명을 앞에 */
    .table-cards > tbody > tr > td.cell-title { order: -1; }                             /* 제목을 맨 위로 */
}
```

HTML 은 표 하나 그대로 두고 CSS 만으로 바꾼다. PC 화면과 모바일 화면을 따로 만들지 않으므로 권한·상태 조건이 한 곳에만 있다. 신청 목록은 공고명 칸을 과제명 아래 보조 글자로 합쳐, PC 에서 과제명이 한 줄에 4~5글자씩 꺾이던 문제도 고쳤다.

### 상세·입력

- 본문 + 오른쪽 요약 카드 (공고: 신청 안내, 신청 과제: 진행 단계, 입력 화면: 작성 안내).
- 진행 단계: 심사탈락은 접수·서류·심사 어느 단계에서도 올 수 있다(`ApplicationStatus`). 상태 이력이 없어 어느 단계에서 탈락했는지 알 수 없으므로, 탈락 과제는 접수완료만 완료로 표시한다.
- 금액 안내(`data-money`): `150000000` → `1억 5,000만원`. 최대 지원금 초과, 자부담금 음수, 정산 잔액 초과는 붉은 글씨로 미리 알린다. 서버 검증은 그대로이고 화면 안내만 추가했다.
- 작성 안내 문구는 코드와 맞췄다. 예: 공고는 등록 즉시 접수중으로 게시되고(`AnnouncementServiceImpl`), 마감은 매일 자정 배치가 처리한다(`AnnouncementCloseScheduler`).

### e-정산

- 금액 4개를 한 상자로 묶고 집행률 막대(승인 파랑 + 검수 대기 주황)를 붙였다.
- 반려 사유·처리 이력을 거래처 칸 안으로 옮겼다. 이전에는 768px 미만에서 숨는 칸에 있어 모바일 사용자는 반려 이유를 볼 수 없었다.
- 승인은 되돌릴 수 없어 확인 창을 거친다. 집행 등록 모달은 닫으면 입력값을 비운다.

## 6. 정적 리소스 캐시

전에는 같은 책(Bootstrap 230KB)을 화면을 옮길 때마다 서점에서 새로 산 셈이었다. 이제는 책장에 1년 꽂아 두고, 개정판이 나오면 표지 번호(해시)가 바뀌어 새 책을 산다.

| | 이전 | 이후 |
| :--- | :--- | :--- |
| CSS·JS·글꼴 응답 | `Cache-Control: no-cache, no-store` (Spring Security 기본값) | `max-age=31536000, public` |
| 화면에 나가는 주소 | `/css/dpms.css` | `/css/dpms-<MD5>.css` (내용이 바뀌면 주소도 바뀜) |
| CSS 안의 글꼴 주소 | — | Spring 이 해시 주소로 바꿔 내보냄 (`CssLinkResourceTransformer`) |
| WebJars | `/webjars/bootstrap/dist/…` | `/webjars/bootstrap/5.3.3/dist/…` (버전이 주소에 들어감) |
| 화면(HTML) | no-store | 그대로 no-store (로그인 화면이 공용 PC 에 남지 않게) |

- 설정은 `application.yml` 의 `spring.web.resources` 한 곳이다. 템플릿의 `@{/css/dpms.css}` 는 그대로 두면 Spring 이 해시 주소로 바꿔 출력한다.
- `/favicon.svg` 는 보안 설정의 허용 경로와 주소가 같아야 해서 해시 대상에서 뺐다. 화면 로고는 `/images/logo.svg` 로 따로 둔다.
- 로컬 프로필은 해시 계산 결과를 저장하지 않는다(`chain.cache: false`). CSS 를 고치면 바로 새 주소가 나온다.

## 7. 접근성 수치

WCAG 상대 휘도 공식으로 계산했다.

| 대상 | 이전 | 이번 | 기준 |
| :--- | :--- | :--- | :--- |
| 포커스 표시 | `#ffb800` / 흰색 1.7:1 | `#0b50d0` / 흰색 6.8:1 (회색 바탕 6.3:1) | 3:1 |
| 입력칸 테두리 | `#d3d9e1` / 흰색 1.4:1 | `#58616a` / 흰색 6.3:1 | 3:1 |
| 주 버튼 글자 | — | 흰색 / `#256ef4` 4.55:1 | 4.5:1 |
| 보조 글자 | — | `#464c53` / 흰색 8.7:1 | 4.5:1 |
| 상태 배지 | — | 승인 7.0:1, 검수요청 8.4:1, 반려 8.0:1 | 4.5:1 |

- 금액·첨부 안내 문구는 `aria-describedby` 로 입력칸에 연결하고 `aria-live` 로 바뀔 때 읽힌다.
- 마감 D-day 는 화면에 `D-7`, 화면낭독기에는 "마감 7일 전"으로 읽힌다.
- 모바일 메뉴 버튼은 아이콘만 두지 않고 "메뉴" 글자를 함께 쓴다.

## 8. 검증

- `./mvnw clean verify` — 156건 성공. 커밋마다 실행
- 헤드리스 Chrome(CDP) — 35개 화면 × 1366·390px, 70장 전체 캡처. 콘솔 오류·CSP 위반·가로 넘침·라벨 없는 입력칸 0건
- 실제 입력 확인 — 신청서 금액 안내(한글 단위, 최대 지원금 초과, 자부담금 음수), 정산 부가세·잔액 초과, 집행률 막대 16.5%·24.2%, 총점 자동 계산
- 글꼴 — 브라우저에서 400·500·700 로드, 완성형 2,350자와 소스에 쓰인 한글 540자 포함 확인
