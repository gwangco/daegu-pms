# 공통컴포넌트 사용 내역

원본: [egovframe-common-components](https://github.com/eGovFramework/egovframe-common-components) v5.0.7 (Apache License 2.0, 사본은 [licenses/](../licenses/egovframe-common-components-LICENSE.txt))

공통컴포넌트는 로그인, 게시판, 첨부파일처럼 어느 시스템에나 있는 기능을 미리 만들어 둔 소스다. 실무에서는 필요한 것만 가져와 프로젝트에 맞게 고쳐 쓴다. 이 문서는 무엇을 가져왔고 무엇을 고쳤는지 적어 두는 곳이다. 원본을 업데이트할 때 이 문서와 각 파일 머리말의 개정이력을 보고 다시 반영한다.

## 가져온 것

| 컴포넌트 | 쓰는 곳 |
| :--- | :--- |
| 공통코드 (`EgovCmmUseService`) | 지원 분야, 비목, FAQ 분류 선택 상자 |
| 첨부파일 (`EgovFileMngService`) | 사업계획서, 정산 증빙, 공지 첨부 |
| 게시판 (`EgovArticleService`) | 공지사항 |
| FAQ (`EgovFaqService`) | 자주 묻는 질문 |
| 채번 (ID Generation, `COMTECOPSEQ`) | 접수번호, 첨부파일, 게시물, FAQ ID |

서비스, DAO, SQL 만 가져왔고 화면(JSP)과 컨트롤러는 가져오지 않았다. 화면은 이 프로젝트의 Thymeleaf 레이아웃으로 만들었다. 로그인·권한(`uat`, `sec`)과 회원 관리(`uss.umt`)도 가져오지 않았는데, 이유는 [비교 문서](UAT_SEC_COMPARISON.md)에 있다.

## 연결 방식

업무 컨트롤러가 업무 서비스를 부르고, 업무 서비스가 권한과 입력을 확인한 뒤 공통컴포넌트 서비스를 부른다.

```text
NoticeController → NoticeServiceImpl → EgovArticleService → EgovArticleDAO → EgovArticle_SQL_mysql.xml
```

- 공통컴포넌트는 원본 패키지(`egovframework.com`) 그대로 둬서 원본과 파일 단위로 비교하기 쉽게 했다.
- 공통컴포넌트 DAO 도 업무 Mapper 와 같은 SqlSessionFactory 를 쓴다. 그래서 트랜잭션과 감사 인터셉터가 같이 적용된다.
- 트랜잭션과 예외 후처리 대상에 `egovframework.com..service.impl.*Impl` 을 추가했다.

## 원본에서 고친 것

### 공통

- 작성자와 수정 일시는 화면 값이 아니라 `#{audit.userId}`, `#{audit.now}` 로 저장한다.
- 수정과 삭제가 처리 건수를 돌려주게 해서, 없는 글이면 404 로 답한다.

### 게시판 (공지사항)

- 상세 조회가 조회수를 같이 올리던 것을 나눴다. `select*` 는 읽기 전용 트랜잭션이라 MySQL 이 UPDATE 를 거부한다.
- 조회수를 "읽고 1 더해서 저장" 두 단계에서 `RDCNT = RDCNT + 1` 한 번으로 바꿨다. 동시에 열면 증가분이 사라졌다.
- 검색 조건을 `searchCnd == 0` 숫자 비교에서 문자열 비교로 바꿨다. 숫자가 아닌 값이 오면 500 이 났다.
- 수정할 때 화면에 없는 컬럼까지 덮어쓰던 것을 제목, 내용, 중요 여부만 바꾸게 했다.
- 상세 조회에서 게시물 비밀번호 컬럼을 빼고, 삭제할 때 제목을 덮어쓰지 않고 `USE_AT` 만 바꾼다.
- 첨부 ID 는 서버가 만든 값만 저장하고, 이미 연결된 첨부 ID 는 바꾸지 않는다.

### FAQ

- 분류, 표시 순서, 사용 여부 컬럼을 추가하고 삭제는 논리 삭제로 바꿨다.
- 등록과 수정에서 화면이 보낸 첨부파일 ID 를 받지 않는다. 남의 첨부파일을 연결해서 받을 수 있었다.

### 첨부파일

- 저장 경로를 서버 절대 경로가 아니라 업로드 폴더 아래 경로(`yyyy/MM`)로 저장한다. 서버를 옮겨도 DB 를 고칠 필요가 없다.
- 파일을 지우기 전에 경로가 업로드 폴더 안인지 확인한다(`../` 경로 조작 방지).
- 삭제할 때 DB 보다 파일을 먼저 지우던 것을 커밋 뒤에 지우게 바꿨다. 롤백되면 파일만 사라지는 문제가 있었다.
- 업로드 유틸과 다운로드 컨트롤러는 가져오지 않았다. 업로드 검사(확장자, 파일 시그니처)는 이 프로젝트의 `FileService` 가 하고, 다운로드는 주소마다 권한을 다시 확인한다.

### 공통코드

- 상세코드 조회에 정렬 순서를 넣었다.
- 코드 ID 는 공통컴포넌트 규칙에 맞춰 `DPM001`(지원 분야)부터 `DPM005`(FAQ 분류)까지 정했다.

## 기존 데이터 옮기기

Flyway `V2` 가 옛 테이블의 데이터를 공통컴포넌트 테이블로 옮기고 옛 테이블을 지운다. 이때 ID 형식도 바뀐다. 예를 들어 파일 번호 `1` 은 `FILE_000000000000001` 이 된다. `V3` 는 공지 게시판의 첨부 설정(허용, 3개, 10MB)만 바꾼다.

## 원본을 업데이트할 때

1. 새 태그와 `git diff` 로 비교한다.
2. 원본 변경을 반영하고 위에서 고친 것을 다시 적용한다. 각 파일 머리말 개정이력의 "D-PMS 적용" 줄이 체크리스트다.
3. 테이블이 바뀌었으면 새 Flyway 버전으로 추가한다. 이미 적용한 파일은 고치지 않는다.
4. `./mvnw clean verify` 로 전체 테스트를 확인한다.
